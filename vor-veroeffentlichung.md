# Checkliste vor der GitHub-Veröffentlichung

- [ ] Zustimmung der Teammitglieder zur Veröffentlichung der gemeinsamen SQL-Abfragen und Präsentationsabbildungen einholen.
- [ ] Prüfen, dass verwendete Quelldaten/Datenmodelle gemäß Lehrveranstaltung tatsächlich öffentlich geteilt werden dürfen.
- [ ] Keine Dozenten-Fallstudie, Seminarfolien oder Originaldatensätze hochladen.
- [ ] Keine API-Keys, Databricks-Tokens, Workspace-URLs mit Geheimnissen oder `.env`-Dateien hochladen.
- [ ] Alle Screenshots vor der Veröffentlichung auf fremde Namen, Konto- und Kundendaten prüfen.
- [ ] Das Repository zuerst **Private** erstellen und erst nach Freigabe auf **Public** umstellen.
- [ ] Prüfen, ob in der README nur Leistungen genannt sind, die die Gruppenunterlagen tatsächlich belegen.

**Hinweis:** Das Paket enthält die vier SQL-Dateien aus der bereitgestellten Gruppendokumentation (umstrukturiert, mit kurzen Hinweiskommentaren), aber weder einen Code-Export der Bronze-Stufe noch Original-Rohdaten. Es wurden keine Databricks-Zugangsdaten hinzugefügt.
